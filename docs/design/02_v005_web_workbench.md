# 中文网页工作台使用说明

版本：V005 / 0.2.0 · 日期：2026-11-25（北京时间）。

## 打开与关闭

在 Windows 资源管理器中打开项目目录，双击 `启动越位分析.vbs`。脚本调用 Python 的无窗口入口 `launch_web.pyw`，自动选择空闲本机端口并打开默认浏览器。重复启动会优先打开同一工作台。无需输入终端命令，也无需安装 Node.js。

本机已配置 Python、NumPy 和 OpenCV。换电脑时需要先安装 Python 3.10+、NumPy、OpenCV；启动器优先使用项目 `.venv`，其次使用 PATH 中的 `pythonw.exe`。启动失败会弹出错误窗口，详情保存在 `.local/startup-error.log`。

关闭浏览器标签页不会关闭后台服务。请点击页面右上角「关闭工作台」。处理中的任务会先完成再退出。重新启动后需要重新导入；已生成文件仍保存在本机。

## 体验演示

点击「体验演示」，服务实际生成一个合成视频和配套标注，并调用现有处理管线，产出 24 帧鸟瞰视频与三个事件：未发现越位位置、越位接球候选、防线不完整。演示用于检查交互和工程通路，不代表真实比赛识别效果。

## 导入自己的素材

| 素材 | 内容 | 约束 |
|---|---|---|
| 比赛视频 | 固定机位拍摄的视频 | 能被本机 OpenCV 解码；最大 4 GB |
| 球场标定 | 源图像点与球场平面坐标的对应关系 | JSON，最大 20 MB；至少四组非退化对应点；不同机位分别标定 |
| 传球与跟踪 | `events` 列表和可选 `tracks` 列表 | JSON，最大 20 MB；帧号从 0 开始，不能超出视频范围 |

JSON 格式参考 `examples/calibration.example.json` 和 `examples/events.example.json`。示例数据是合成坐标，不能直接用于任意比赛视频。鸟瞰输出宽高须为 100–3840 之间的偶数。

三个文件选择齐全后，「生成鸟瞰结果」按钮才会启用。支持拖入单个视频。服务在后台队列中处理任务，页面显示导入进度和视频生成进度；失败会显示原因，允许重新选择并重试。

当前前端接入的是 V004 数据接口：不会自行识别所有传球、自动生成标定、恢复三维身体点或调用 LLM。干扰提示阈值只作用于事件文件内已有的概率；达到阈值的结果在界面标为待复核。原型规则判断仍需逐案复核，本版未扩大自动判罚能力。

## 查看和导出

- 「传球事件」表列出时间、触球帧、状态和相关球员。点击「查看」切换鸟瞰帧。
- 「查看所选事件的原始画面」展开触球时刻原视频截图，便于对照。
- 鸟瞰图内点的填充颜色表示有效部位：红色头部、黄色躯干/肩部、蓝色脚部（沿用原型颜色）；外圈橙色为进攻队、蓝色为防守队（A/D 示例）。
- 「下载视频」导出 MP4；「事件报告」导出 JSON，包括事件帧号、时间、状态和说明。网页预览使用事件图片，避免不同浏览器对 MP4 编码的兼容性影响查看；完整视频可下载后在本机播放器打开。
- 没有逐帧 `tracks` 的片段只显示球场，不能把冻结的传球帧当作持续跟踪结果。

## 本机存储与技术结构

浏览器只与 `127.0.0.1` 上的本机服务交互，不依赖 CDN、云存储或外部模型服务。素材、预览、MP4 和报告保存在 `.local/web-jobs/<任务编号>/`。此目录已忽略，不会上传 GitHub；文件保留至用户自行清理。

前端采用原生 HTML/CSS/JavaScript；后端采用 Python 标准库 HTTP 服务和单工作线程任务队列。网页资源随 Python 包分发，增加 `offside-web` 入口；原有 CLI 继续可用。任务状态驻留在进程内，页面刷新可恢复当前任务，服务重启后不恢复历史任务列表。

修复 V004 逐帧轨迹渲染误引用 `decision` 的错误，并为视频管线增加进度回调和空视频检查。OpenCV 自带字体无法绘制中文，图内使用状态编码，网页与报告提供中文说明。

## 验证范围

使用合成视频验证文件上传、任务处理、逐帧轨迹、事件截图、报告和视频下载；覆盖事件帧越界和跨来源请求拒绝。浏览器中核查演示、事件切换、原始帧展开、指南以及桌面/窄屏布局。真实比赛视频的模型和几何精度仍未验证。
